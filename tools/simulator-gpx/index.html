Simulator GPX Builder and Fixer

Make a route file that Xcode's iOS Simulator and the Android Emulator will actually play, timed for the speed you choose. Or drop in a GPX file that won't move and see exactly what is wrong with it.

Private by design. Nothing you draw, paste or drop is uploaded. Map tiles come from OpenFreeMap. Once the map is open it zooms to your route, so OpenFreeMap sees that area.

1 Add your route

Use decimal lat, lon, degrees-minutes-seconds, or a full Google Maps, Apple Maps or OpenStreetMap link. Lines starting with # are ignored.

    Drop a GPX, KML, GeoJSON or CSV file here, or . 4 MB at most. The file is read on this device and checked by the GPX doctor.

    route-xcode.gpx for Xcode and the iOS Simulator

    GPX 1.1 with waypoints only, in time order, each with a whole-second UTC time. No track or route tags, because Xcode does not support them.

    
        
    
          How to use it in Xcode
          
      
            
    1. Add the file to your project: drag it into the Project navigator.
      2. 
            
    2. Run your app, then click the Simulate Location button in the debug bar (the location arrow) and choose the file, or choose Add GPX File to Project… there.
      3. 
            
    3. To start with it every run, choose Edit Scheme > Run > Options, tick Allow Location Simulation and pick the file under Default Location.
      4. 
          
    
        
    
      
    

      
    
        
    route-android.gpx for the Android Emulator
    
        
    GPX 1.1 with one track and one segment. Every point has a whole-second time later than the one before, because the emulator reads whole seconds and sorts points by time.
    
        
    
          
          
        
    
        
    
        
    
          How to use it in the emulator
          
      
            
    1. Click More in the emulator panel to open Extended controls, then choose Location.
      2. 
            
    2. Open the Routes tab and click Import GPX/KML. Google's guide and older builds call the button Load GPX/KML.
      3. 
            
    3. Pick the file, leave the speed at 1X, then click Play Route (Run in Google's guide).
      4. 
          
    
        
    
      
    

      
    
        
    simctl command for a booted iOS Simulator
    
        
    No project or file needed. simctl moves between your points at the speed you set and sends an update every interval.
    
        
    
          
        
    
        
    
        
    Paste it into Terminal on a Mac with Xcode installed. Stop the route with xcrun simctl location booted clear. simctl cannot pause, so it ignores the dwell setting.
    
      
    

      
    
        
    route-adb.sh script for the Android Emulator console
    
        
    Sends one adb emu geo fix per interval, then sleeps. Useful in test scripts and CI.
    
        
    
          
          
        
    
        
    
        
    Longitude comes first. geo fix takes longitude, then latitude, the reverse of the usual order. The script already has them the right way round. Run it with sh route-adb.sh on macOS, Linux or Git Bash while one emulator is running. Under WSL, adb has to be set up to reach an emulator running on Windows first.
    
      
    

      
    
        
    Plain route.gpx and route.geojson
    
        
    Just the shape: the points you entered, with no timing. For Wander or any other app that sets its own pace. The GPX is a single track. The GeoJSON is a LineString with positions in longitude, latitude order.
    
        
    
          
          
          
          
        
    
      
    

      
    
        
    Link to this route
    
        
    The route is stored after the # in the link. Browsers never send that part of an address to a server (RFC 3986), and this page removes it from the address bar as soon as it has read it. Points are rounded to about 1 metre.
    
        
        
        
    
          
        
    
        
    
      
    
    
    

    
    
    
      
    Why your GPX won't move in Xcode or the emulator
    
      
    GPX (GPS Exchange Format) is an XML file format for location data. The GPX 1.1 schema gives a file three ways to hold a point: a waypoint (<wpt>), a route point (<rtept> inside <rte>) and a track point (<trkpt> inside <trk> and <trkseg>). The schema describes a track as an ordered list of points describing a path, so that is how a recorded trip is normally saved. Xcode and the Android Emulator read these files in different ways, and most "it loads but nothing moves" problems come from that difference.
    

      
    Xcode plays waypoints and nothing else
    
      
    Apple's Xcode Help is direct about this. Its page on simulating a location in the debugger says a GPX file may hold a series of waypoints using the wpt tag, and that the rte and trk tags are not supported. The page on the scheme editor says the same. A track exported from another app can be perfectly valid GPX and still contain no point that Xcode will use.
    
      
    Timing is the second trap. The GPX File template in Xcode's New File dialog (File > New > File, then GPX File) carries a comment with the rules. Give each waypoint a <time> and Xcode moves at a speed based on the time between waypoints. Leave the times out and Xcode uses a fixed speed. Either way, waypoints must be sorted by time in ascending order. The error messages built into Xcode 27.2 are stricter still: a time has to be in ISO 8601 form without milliseconds, each waypoint has to be later than the one before it, and a waypoint may carry only one time element. Going by those messages, one bad waypoint makes Xcode reject the whole file. Xcode shows them when you pick a bad GPX file under Simulate Location. Apple does not publish the template or these messages online; we read them in Xcode 27.2.
    
      
    Developers still disagree about how closely Xcode follows those times. In a long-running Stack Overflow thread about controlling speed with GPX, one answer quotes the template and says the times set the speed. Another reports that the simulator took the same time between any two points, whatever the distance, and that the fix was to add many evenly spaced points. This tool does both. If Xcode follows the times, the route moves at your chosen speed. If it steps through one point per location update instead, the even spacing still gives a steady pace, and at the default 1-second interval it should come out close to your speed. We have not measured Xcode's playback speed ourselves.
    

      
    The Android Emulator reads every point, then sorts by time
    
      
    The emulator is relaxed about structure. Its open-source GPX parser reads waypoints, route points and track points alike. What it cares about is time, in three ways.
    
      
      
        
    • Whole seconds only. The parser reads each <time> as six whole numbers: year, month, day, hour, minute and second. Nothing after the seconds is read, so fractions of a second are dropped and an offset such as +02:00 is not applied.
      • 
        
    • Points are sorted by time. After reading the file, the parser sorts every point by its time. A file with out-of-order times plays in a different order than it was written.
      • 
        
    • The gap between times is the delay. The emulator's route code (location-page-route.cpp and location-page-route-playback.cpp) turns the difference between each point's time and the previous point's time into the delay before that point, so points that share a whole-second time play with no pause between them. A track logged ten times a second, or a file with no times at all, will not play at the speed it was recorded.
      • 
      
    
      
    To load a file, Google's extended controls guide says to open Location, click Load GPX/KML, pick the file, optionally choose a speed multiplier and run it. In the current emulator source the button is labelled Import GPX/KML and sits on the Routes tab.
    

      
    What this tool changes
    
      
    The builder resamples your route so that consecutive points are speed × interval apart, measured along the path. At walking pace (1.4 m/s) with a 1 second interval, that is one point every 1.4 m. Sharp corners and turnarounds are kept exactly, so the gap just before each one can be shorter, and the summary in step 3 says how many there are. It then stamps each point with a whole-second UTC time, one interval after the last. The Xcode file holds only waypoints. The Android file holds one track with one segment. A simulator that follows the times moves at your chosen speed. A simulator that steps through one point per update still moves at a steady pace, but that pace matches your speed only when its update period equals the interval you set.
    

      
    Two command-line traps
    
      
    simctl and negative latitudes. xcrun simctl location booted start takes a speed and a list of lat,lon waypoints and does its own interpolation, so it needs no GPX file. When we ran it on Xcode 27.2, a waypoint with a negative latitude, such as -33.8688,151.2093, was read as a command-line option and the command stopped with an "invalid option" error. Putting -- before the waypoints fixed it, and so did sending them on standard input with -. Every route command this page builds uses one of the two. A single point uses simctl's set action instead, which reads negative latitudes correctly.
    
      
    adb and longitude first. Google's emulator console guide documents the command as geo fix longitude latitude. That is the reverse of the usual "lat, lon" order, and of simctl. Swap the two and the emulator lands somewhere else entirely. The script this page builds keeps the order right.
    

      
    Limits worth knowing
    
      
      
        
    • Points are joined by straight lines. Nothing here snaps to roads, so add a point wherever your path turns.
      • 
        
    • The files contain clean, exact positions. Real GPS drift and signal loss are not simulated.
      • 
      
    
    
    

    
    
      
    Ready to test on a real phone?
    
      
    The simulator is not a real phone. To walk this route on a real iPhone or Android, import the plain route.gpx into Wander (GPX import is a Pro feature). Some apps' terms forbid changing your location, so check the terms of the apps you use it with.
