'Select Mock Location App' Not Showing or Not Working on Android: How to Fix It

"Select mock location app" is hidden inside Developer options, so it won't appear until you unlock that screen by tapping Build number seven times. If the setting is there but your app isn't listed, install the app first: Android only lists installed apps that ask for mock-location permission.

Published 15 November 2026 · 10 min read

Quick answer: "Select mock location app" lives in Developer options. On Android 12 and later it's under the Location heading near the bottom of that screen. On Android 11 and earlier it's under Debugging. Phone makers can move it, so the fastest way on any phone is to search Settings for mock. If you can't see it, Developer options is probably still locked. Tap Build number seven times to unlock it. If the setting is there but your app isn't in the list, the app isn't installed yet, or it doesn't ask Android for mock-location access. A work or school device, a second user account, or a very old Android version can also hide it.

What "Select mock location app" does

A mock location is a made-up position that an app gives Android in place of your real one. Developer options is a hidden Settings screen with tools for people who build and test apps, such as USB debugging.

"Select mock location app" sits inside Developer options. Google describes it as a way to fake the device's GPS location "to test whether your app behaves the same in other locations." You pick one app from a list. That app then gets permission to supply the phone's location.

Only one app can hold that permission at a time. In Android's own Settings code, picking a new app takes the permission away from the old one. Picking Nothing takes it away from every app.

Google's guide adds one more detail: you have to install a mock location app before you can use the setting. That detail explains most "it's not showing" problems.

Step 1: Unlock Developer options

Since Android 4.2, Developer options is hidden until you unlock it. You unlock it by tapping the Build number, a line in your phone's About screen. Google's guide lists where to find it on several phones, including these:

PhoneWhere to find Build number
Google PixelSettings > About phone > Build number
Samsung Galaxy S8 and laterSettings > About phone > Software information > Build number
OnePlus 5T and laterSettings > About phone > Build number

Other phone makers use different menus and labels, and Google's guide notes that on some phones the Developer options screen is located or named differently. If your phone isn't in the table, check your phone maker's help pages.

  1. Open the Build number line for your phone, using the table above.
  2. Tap Build number seven times, until you see "You are now a developer!"
  3. If you use a screen lock, enter your PIN, pattern or password when asked.
  4. Go back. Developer options now appears in Settings.

Where it appears depends on the phone. On a recent Pixel, look in Settings > System > Developer options. Some older Android versions put it under System > Advanced instead. On a Samsung Galaxy, Samsung says it appears at the very bottom of the main Settings menu.

Samsung is one level deeper. On a Galaxy, Build number isn't on the About phone screen itself. Open Software information first, then tap Build number.

Step 2: Find "Select mock location app"

Open Developer options. Where the setting sits depends on your Android version:

  • Android 12 and later: scroll near the bottom of Developer options to the Location heading.
  • Android 11 and earlier: look under the Debugging heading instead.

Android's own Settings layout file shows this move. Google's developer guide still describes the setting among its debugging options, so a Pixel owner on a recent version who scrolls to Debugging won't find it there. On stock Android, as on a Pixel, the setting is called "Select mock location app". Under the name, Android shows either "No mock location app set" or "Mock location app:" followed by the app's name.

Developer options is a long list, and phone makers can move things around in it. Searching is usually faster than scrolling:

  1. Open Settings.
  2. Tap the search bar or magnifying glass.
  3. Type mock.
  4. Tap the result that mentions a mock location app.

If search finds nothing, Developer options is probably locked or switched off. The next section covers that.

The option is missing entirely

The Developer options switch is off

Developer options has a main switch at the top of its screen. Google says to keep it on, because most options below it are disabled while it's off. Samsung's help uses the same switch to turn Developer options off. Switch it back on and look again.

Switching Developer options off also clears your mock location app. Android's Settings code removes the mock-location permission from every app when you turn the switch off, and turning it back on doesn't restore it. So after you switch it back on, open Select mock location app and pick your app again.

Your phone runs a very old Android version

Before Android 6.0 there was no app picker. There was a checkbox called "Allow mock locations" instead. Google's reference marks that old setting as deprecated in Android 6.0 (API level 23) and says it is no longer used.

A 2016 Android Central thread shows the same thing: a Galaxy J5 on Android 5.1.1 had only an on/off switch. On a phone that old, the checkbox is the setting.

It's a work or school phone

Many employers and schools manage phones with MDM (mobile device management) software. MDM lets an IT admin set rules for a device. Google's Android Management API, which management tools can use, has a developer settings policy. By default, that policy disables all developer settings and stops the user from opening them.

Android also lets an organization block debugging features. If it manages the whole phone, the block applies everywhere. If it only manages a work profile (a separate, badged set of work apps on your own phone), the block covers only that profile. Your personal Developer options are unaffected. Google's docs say the block is on by default for work profiles created on or after the April 2025 security patch.

When a block like this applies, Android's Settings code doesn't show the Developer options list. Instead it shows either a notice that your admin has turned the feature off, or the message "Developer options are not available for this user".

Some MDM tools also have their own mock-location switch. Hexnode's help notes that on fully managed (Device Owner) phones, turning mock locations off there disables Developer options completely.

If an admin has blocked it, you can't turn it back on yourself. Ask your IT team. Don't try to get around a policy on a device someone else controls.

You're signed in as a second user or a guest

Android phones and tablets can have more than one user. In Android's Settings code, Developer options is for admin users only. If you're not the admin user, Android shows the message "Only the admin users can access developer settings." and closes the screen. Switch to the phone owner's account and try again.

My app isn't in the list

This is the most common surprise. The picker doesn't list every app. Android's Settings code builds the list from installed apps that request one permission (a named ability an app asks Android for): ACCESS_MOCK_LOCATION. An app that doesn't request it never appears, whatever it claims to do.

  • Install the app first. The list only shows apps that are already on the phone.
  • Reopen the picker. If the picker was open while you installed the app, back out of it and open it again. Android rebuilds the list each time the picker opens.
  • The list only says "Nothing". No installed app requests the permission yet. Install one that does.
  • The app is installed but still missing. It doesn't request the permission, so it can't be your mock location app. Ask its developer.

If you're building your own mock location app

Declare the permission in your app's manifest:

<uses-permission android:name="android.permission.ACCESS_MOCK_LOCATION" />

Then select your app in Developer options. Until you do, LocationManager.addTestProvider() throws a SecurityException. Google's Fused Location Provider has the same rule: its mock mode needs the permission and needs your app selected as the mock location app.

One more trap, on Android 10 and earlier: calling addTestProvider() a second time with the same name, such as gps, throws an IllegalArgumentException with the message Provider "gps" already exists. A Stack Overflow question about Android 10 hit exactly this. Remove the old test provider with removeTestProvider() before adding it again, or catch the error, and then call setTestProviderLocation(). From Android 11 on, this no longer throws. Google's current LocationManager docs say a new test provider replaces any existing provider with the same name.

It's selected, but my location doesn't change

Selecting an app only gives it permission. It doesn't move you by itself. Work through these checks in order:

  1. Turn Location on. Open Settings > Location and switch on Use location. On Android 9 it's under Security & Location > Location.
  2. Set a location in the app. Open the mock location app and start it. A B4X forum post warns that apps listed as mock providers don't always send a location, so other apps may not get a location fix at all.
  3. Check which app is selected. Only one app can be the mock location app. If you picked a different one later, it replaced the first.
  4. Pick it again if you toggled Developer options. Turning Developer options off clears your mock location app, and turning it back on doesn't restore it. If the setting shows "No mock location app set", open Select mock location app and choose your app again.
  5. Compare two apps. Android has more than one way to deliver a location. A mock app can feed Android's own location providers, or Google's Fused Location Provider (a location service in Google Play services that many apps use). Apps that read from a different source may show a different result.
  6. Restart the phone. Then open the mock app and set the location again.
  7. Confirm in a maps app. Open a map and check where your location dot is.

Why some apps ignore or reject mock locations

Android tells apps when a location is a mock. Each location carries a flag. Since Android 12, apps read it with Location.isMock(). Older versions use isFromMockProvider(), which dates back to Android 4.3.

Google's documentation says users may have a good reason to mock their location. It tells developers to reject mock locations only when real locations are essential to the app.

Some apps reject them anyway. Some also forbid changing your location in their terms of service. If you use a mock location app alongside another app or service, you're responsible for following that service's terms. This guide doesn't cover hiding the mock flag, and we don't help with getting around an app's rules.

If you're a developer, the flag is useful. Test both cases: what your app does with a real location, and what it does when the location is marked as a mock.

FAQ

Do I need root to use a mock location app?

No. Select mock location app is a built-in Android setting. You only need to unlock Developer options and install an app that requests mock-location access.

Why is the mock location app list empty?

The list only shows installed apps that request the ACCESS_MOCK_LOCATION permission. Install a mock location app first, then back out of the picker and open it again.

Can apps tell that my location is a mock location?

Yes. Android marks mock locations, and apps can check that mark. Some apps reject mock locations or forbid location changing in their terms, and you're responsible for following those terms.
