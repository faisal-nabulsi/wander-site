GPX vs KML vs GeoJSON: What Each Route File Stores and Which One Your Tool Needs

GPX, KML and GeoJSON can all hold the same points and paths, so pick the one your destination reads. Use GPX for GPS apps and location simulators, KML or KMZ for Google Earth and My Maps, and GeoJSON for web maps and code.

Quick answer: pick the format your destination reads

GPX, KML and GeoJSON are text formats for map data, and all three can describe the same path. So use the one your destination app reads, because that app decides whether your path shows up at all.

Where is the file going?UseWhy
A GPS device, or an outdoor or fitness appGPXGPX was made for passing GPS data between apps.
A location simulatorGPXXcode's Simulate Location takes GPX waypoints. The Android Emulator loads GPX or KML.
Google Earth or Google My MapsKML or KMZGoogle documents KML as a format for Google Earth, and both tools import it.

A plain list of pointsCSV (comma-separated values)It is a text table with one row per point. My Maps and Google Earth both import it.

    </trkseg>
  </trk>
</gpx>

This sample is a track, and Xcode ignores tracks. For Xcode, write each point as a waypoint (<wpt>) directly inside <gpx>, with its time inside it. This version also passes the GPX 1.1 schema:

Compare the first point in each file. GPX labels both numbers: lat="51.5007" lon="-0.1246". KML and GeoJSON write -0.1246 first, because they put longitude before latitude. Only the GPX and CSV samples carry a time for each point.

CSV has no fixed layout, so each tool decides which columns it accepts.

GPX: made for GPS data

GPX stands for GPS Exchange Format. It is written in XML, a text format that wraps data in nested tags. The current version, GPX 1.1, came out in August 2004.

A GPX file can hold three different things:

  • Waypoint (<wpt>): a single point, such as a point of interest.
  • Route (<rte>): an ordered list of turn points that lead to a destination.
  • Track (<trk>): an ordered list of points that traces a path. Track points sit inside segments (<trkseg>). A new segment starts wherever the recording had a gap, such as lost GPS reception.

Every point names its latitude and longitude as attributes (labels inside the tag, like lat="51.5007"). The values are in decimal degrees (51.5007 rather than degrees, minutes and seconds). All coordinates use WGS84 (World Geodetic System 1984), the model of the Earth that the numbers are measured against. Each point can also carry an elevation in metres and a time in UTC.

The three-way split matters because a tool may read one kind and ignore the rest. Apple's Xcode Help says a GPX file for Xcode may hold waypoints, and that route and track tags are not supported. So a file can be valid GPX and still show nothing: it holds a track, and the tool wanted waypoints. Our Xcode Simulate Location guide covers the fix.

KML and KMZ: made for Google Earth

KML stands for Keyhole Markup Language. Google's KML tutorial describes it as a format for showing geographic data in an Earth browser, such as Google Earth. It is also XML, and an open standard maintained by the Open Geospatial Consortium (OGC).

KML is built around the Placemark: a feature with a geometry. The geometry can be a Point, a LineString (a line) or a Polygon (a closed shape). KML also has styles, which set icons and line colours, and folders, which group features.

Coordinates are written as longitude, latitude, then an optional altitude in metres. Commas separate the values, with no spaces inside one point. A space separates one point from the next.

A plain LineString holds positions only, so it has no time for each point. You can still time single points: give each point its own Placemark with a <TimeStamp>. For a timed path, Google added an extension called gx:Track. It pairs a <when> time with each position. Not every KML reader supports it. Google My Maps warns that time-based KML elements may not import.

A KMZ file is a zipped KML: one main KML file plus any supporting files, such as images.

GeoJSON: made for code

GeoJSON is based on JSON (JavaScript Object Notation), a plain-text data format that is not XML. It is defined by RFC 7946, which the IETF (Internet Engineering Task Force) published in August 2016.

A GeoJSON position is a list of numbers: longitude, latitude, then an optional elevation. Like GPX, it uses WGS 84 and decimal degrees. Geometries include Point, LineString and Polygon. A Feature joins one geometry to a properties object, which can hold any data you like.

GeoJSON has no built-in time for each point and no styling. The RFC advises against adding a fourth number to a position, because readers cannot tell what it means. Times can go in properties, but then each tool decides whether to read them. Files end in .geojson or .json.

The coordinate-order trap

The formats do not agree on which number comes first. Here is our first sample point in each place you might type it.

WhereOrderFirst sample point
Google Maps search boxLatitude, then longitude51.5007, -0.1246
GPXNamed, so order does not matterlat="51.5007" lon="-0.1246"
KMLLongitude, then latitude-0.1246,51.5007
GeoJSONLongitude, then latitude[-0.1246, 51.5007]
Android Emulator geo fix commandLongitude, then latitudegeo fix -0.1246 51.5007

A swapped pair is often still a valid coordinate. It just points somewhere else. We swapped the first point of the GPX sample to test this. The file still passed the schema, and the point moved about 7,500 km.

A GPX validator only catches a swap when the longitude is above 90 or below -90, because no latitude can be. We tried that too, and the GPX schema rejected it. A KML schema check catches no swap at all, because the KML 2.2 schema does not check coordinate ranges. So if a converted path lands in the wrong country or in the sea, check the order first.

What survives conversion

You usually convert because one tool exports a format the next will not read. In 2025, for example, an OpenStreetMap forum user asked for a GPX download, because the site offers routes as GeoJSON and GPS apps often want GPX. But a converter can only keep what the target format has a place for.

FeatureGPXKMLGeoJSON
Single pointsYes (waypoints)YesYes
LinesYes (routes and tracks)YesYes
Polygons (closed shapes)NoYesYes
A time for each pointYesWith gx:Track, or one timed Placemark per pointNo standard place
ElevationYesYesYes
Line colours and stylesNot in the core schemaYesNo
FoldersNoYesNo
Waypoint, route and track splitYesNoNo

KML colours and folders have nowhere to go in a GPX file. GPX times have no standard home in GeoJSON. The togeojson converter keeps them anyway, under a draft convention called coordinateProperties, but a reader has to know to look there.

So keep the original, convert a copy, and open the result in the app you need it for. Dropped data cannot be rebuilt from the copy, and a valid file can still show nothing or land in the wrong place.

Free converters:

  • GPSBabel: free software for Windows, macOS and Linux that converts waypoints, tracks and routes.
  • ogr2ogr: a command-line tool from the open-source GDAL project. It handles GPX, KML and GeoJSON, among many other formats.
  • togeojson: a JavaScript library that turns KML and GPX into GeoJSON.

To convert KML to GPX with GPSBabel:

gpsbabel -i kml -f route.kml -o gpx -F route.gpx

-i and -o name the input and output formats. Case matters: -f is the file you read and -F is the file you write. GPSBabel's documentation says it stores simple KML paths as tracks, so expect a GPX track, not waypoints. If the file is for Xcode, change the track points to waypoints, as in the waypoint sample above.

We built this command from GPSBabel's documentation and have not run it ourselves. Open the result before you rely on it.

Route files for location testing

Developers play route files back as a moving location to test their apps. Here time matters most, because the gap between two timestamps sets the speed. A player that honours timestamps moves at the recorded pace. One that ignores them picks its own speed.

Xcode's GPX file template says Xcode is the first kind. The comment in the template says Xcode sets the speed from the time between waypoints, and uses a fixed speed when there are no times. The Android Emulator plays a loaded file at 1X by default. Google's guide says 1X uses the file's Delay value, the time gap between points. You can raise the speed to 2X, 3X and so on.

So when pace matters, start from a format that keeps a time for each point: GPX, or CSV with a time column if your tool reads one. For Xcode, those GPX points must be waypoints, not a track. A plain KML or GeoJSON line carries no times, so the player has nothing to pace itself with.

FAQ

Is KML or GPX better for Google Maps?

Google's custom map tool, My Maps, imports both. Google warns that some KML data may not import, such as time-based elements and folders. For a simple path, use whichever format you already have.

Can I open a GPX file in Google Earth?

Not directly on the web or on mobile. Google's documentation says to convert it to KML, GeoJSON, CSV or Shapefile first. The desktop app, Google Earth Pro, is different. Google Earth Help's page on importing GPS data, whose steps use the desktop Tools menu, says to drag a .gpx file into Google Earth.

Does GeoJSON store time or speed?

Not in a standard way. A GeoJSON position holds longitude, latitude and an optional elevation. Times can go in a feature's properties, but each tool decides whether to read them.

What is a KMZ file?

A zip archive that holds one main KML file plus any supporting files, such as images. To look inside, change the extension to .zip and unzip it.

How do I convert KML to GPX?

Use a free converter such as GPSBabel or GDAL's ogr2ogr. Keep the original, and open the result in the app you need it for. KML colours and folders will not carry over, because GPX has no place for them.
