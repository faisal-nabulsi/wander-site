How to Set a Location in the Android Emulator (and Fix It When It Won't Update)

Open Extended controls with the More button in the emulator panel, choose Location, pick a point and click Set location. From a terminal, run adb emu geo fix with the longitude first, then the latitude.

Quick answer: three ways, easiest first

  1. The Location panel. Click More (the three-dot button) in the emulator panel to open Extended controls, the emulator's settings window. Choose Location, pick a point and click Set location.
  2. One command. adb emu geo fix <longitude> <latitude> sends a GPS fix (one position reading) to the running emulator.
  3. A route file. In the Location panel, click Load GPX/KML, choose a file and click Run.

Two details trip people up. geo fix takes the longitude first, so a "latitude, longitude" pair copied from a map goes in backwards. And Google says some extended controls only work when the emulator runs in its own window, not docked inside Android Studio. If your app doesn't react, go to the fix table.

How we checked this. We did not run these steps on an emulator. Menu names and syntax come from Google's Android Developers pages as of 15 November 2026, and from the open-source code of the emulator console and adb. The newest emulator release then was 37.2.13 (28 October 2026). Google's next-generation emulator, in preview in Android Studio Canary, may differ.

Set one location (Single points tab)

  1. On the Single points tab (the other is Routes), search for a place or click the map.
  2. Optional: click Save point. Saved points are listed on the right.
  3. Click Set location, near the bottom right.

Google says this map stopped working from mid-May (2024, going by the release notes) in emulator versions before 34.2.13, because those older versions ship a Chromium (the browser engine that draws the map) that is incompatible with the Google Maps JavaScript API. Help > About in Extended controls shows your version. To update, use Tools > SDK Manager in Android Studio.

Play a route (Routes tab)

  1. On the Routes tab, search for the first destination and select it.
  2. Click Navigate, then choose the starting point on the map.
  3. Optional: click Add destination for more stops.
  4. Click Save route, name it and click Save.
  5. Pick it under Saved routes and click Play route. Stop route ends it.

The Repeat playback switch loops the route. The Playback speed menu sets how fast the emulator moves.

Play a GPX or KML file

GPX (GPS Exchange Format) and KML (Keyhole Markup Language) are file types that store GPS points. They are the only two Google lists for the emulator.

  1. In the Location panel, click Load GPX/KML.
  2. Choose the file and click Open.
  3. Optional: pick a Speed. It defaults to 1X. 2X doubles it, 3X triples it, and so on.
  4. Click Run.

Not sure which file to make? See GPX vs KML vs GeoJSON. To build one, try our Simulator GPX Builder and Fixer.

From the command line

Every running emulator has a console, a text interface for controlling it. adb emu sends it one command and returns. (adb, the Android Debug Bridge, is Android's command-line tool for devices.)

adb emu geo fix -122.0300 37.3320

That is longitude -122.0300, then latitude 37.3320. The full form:

geo fix longitude latitude [altitude] [satellites] [velocity]

Longitude and latitude are in decimal degrees, altitude in metres and velocity in knots. Satellites is a whole number from 1 to 12. Bracketed parts are optional. With several emulators running, name one with -s (adb devices lists the names):

adb -s emulator-5554 emu geo fix -122.0300 37.3320

The telnet console

Telnet is a simple text-based connection tool. Google says the first emulator uses console port 5554, and adb devices shows each emulator's port.

Your computer may not have telnet. Microsoft says Windows needs the telnet client installed first, and our Mac on macOS 26.6 had no telnet command. adb emu does the same job without it.

telnet localhost 5554
auth YOUR_TOKEN
geo fix -122.0300 37.3320
quit

The console wants auth first. The token is the text inside .emulator_console_auth_token in your home folder. Going by adb's source code, adb emu reads that file and sends auth for you.

Raw NMEA sentences

geo nmea sends one NMEA 0183 sentence (a line of text in a GPS receiver's format) starting with $GP. Google's page lists $GPGGA and $GPRCM; the emulator's source code says $GPRMC, so the page looks like it has a typo.

Script a walk

This bash or zsh loop moves north about 22 metres every 15 seconds, close to walking pace. We checked it with a stand-in for adb, not a live emulator.

# Walk north from 37.3280 to 37.3288, one step every 15 seconds
lon=-122.0300
for lat in 37.3280 37.3282 37.3284 37.3286 37.3288; do
  adb emu geo fix "$lon" "$lat"
  sleep 15
done

For CI (continuous integration: tests that run automatically on a server), Google offers a gRPC interface that lets programs call the emulator directly. Start the emulator with -grpc and a port, for example emulator -grpc localhost:8556 @YourDevice. Google maps geo fix to the method EmulatorController/setGps.

How the emulator's location reaches your app

Google says the emulator sets your location by creating a mock location provider, a stand-in source of location data. It answers the listeners apps register and supplies the fix to LocationManager, Android's built-in location service. Apps can read it with LocationManager.getLastKnownLocation("gps").

Apps can also use the fused location provider, a Google Play services API that manages the underlying location technology for them. Our reading, not Google's statement: those apps get the emulator's fix second-hand, through Play services. That would explain why several fixes below involve Play services.

adb emu does not work on a real phone

adb emu talks to the emulator console, which a physical phone doesn't have. In adb's source code, it only looks for devices named emulator- plus a number. On a real Android phone, choose an app under Developer options > Select mock location app instead. Google describes it as a way to fake the GPS location with a mock location app you install. If the setting or app is missing, see mock location app not showing.

The emulator also can't show how real readings behave indoors or on the move (see how your phone knows where you are). Battery rules differ too. The emulator's Battery panel says Charging by default, Google says App Standby limits apply only on battery power, and each phone maker sets its own rules for idle apps. Our suggestion: set Charger connection to None (and Battery status to Discharging) before testing background behaviour, then confirm on a real phone. Google's Doze and App Standby test steps use adb shell dumpsys battery unplug for the same job. For a full testing plan, see test geofencing without driving; for iPhone apps, Xcode Simulate Location not working.

FAQ

Is it latitude or longitude first in geo fix?

Longitude first. For latitude 37.3320 and longitude -122.0300, type adb emu geo fix -122.0300 37.3320.

Why does the emulator think it is in California?

This is community-reported. A 2021 Stack Overflow answer describes an emulator stuck in Mountain View, California, and a 2019 answer calls Cupertino the default. In both, opening a map in the emulator picked up the new place. The Google pages we read name no default.

Can I set the emulator location from a script or CI job?

Yes. Loop adb emu geo fix with pauses, as in the script above, or call Google's gRPC method EmulatorController/setGps.

Can the emulator load a GeoJSON file?

Google's page lists only GPX and KML, so convert GeoJSON first. Our Simulator GPX Builder and Fixer reads a GeoJSON file and rebuilds it as a GPX file for the emulator. Our route file guide explains the formats.
