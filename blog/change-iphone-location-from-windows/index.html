How to Set a Real iPhone's Location From a Windows PC: pymobiledevice3, GeoPort and Wander Desktop Compared

You can set a real iPhone's GPS location from a Windows PC with no Mac and no Xcode, Apple's Mac developer app. On iOS 17 and later, use a tool built for Apple's newer developer tunnel: pymobiledevice3 and GeoPort are free, and Wander Desktop has a free plan.

The short answer

You don't need a Mac or Xcode to set a real iPhone's location. A Windows PC, a USB data cable and the right tool are enough. The catch is iOS 17. Apple moved the iPhone's developer features, including location simulation, behind an encrypted tunnel, so older tools stopped working (details below). Three tools built for Apple's iOS 17+ developer tunnel are pymobiledevice3, GeoPort and Wander Desktop. Open reports on GeoPort's issue tracker say it doesn't change the location on iOS 26.4.1 or iOS 27, so check them before you rely on it.

A few terms from the table. GPL v3 is an open-source license. UAC (User Account Control) is the Windows prompt that asks before an app gets admin rights. A Python API lets your own Python code control the tool. A GPX file is a standard format for GPS tracks.

We checked each project's own pages on 15 November 2026, but did not hands-on test every tool on every iOS release. Apple can change its developer features in any iOS update, so check a tool's issue tracker or changelog after you update.

What you need before you start

  1. iTunes. Install iTunes from apple.com. It adds the Apple Mobile Device Service, the background service that lets Windows talk to an iPhone. All three tools work with it. pymobiledevice3's docs prefer it to the Microsoft Store's Apple Devices app, because the Store app can't find iPhones over Wi-Fi. GeoPort's README asks for iTunes. Wander Desktop also accepts the Apple Devices app.
  2. A USB cable that carries data. Apple says the cable must support both data and charging.
  3. A trusted connection. Unlock the iPhone and plug it in. When it asks "Trust This Computer?", tap Trust and enter your passcode.
  4. Developer Mode on the iPhone, for DVT-based tools. DVT is the developer-tools service that Xcode uses; on iOS 17 and later, location simulation goes through it. This requirement comes from pymobiledevice3's docs, which say that on iOS 17 and later, DVT needs Developer Mode but no disk image. It covers pymobiledevice3 and GeoPort, which is built on pymobiledevice3. Wander's download page doesn't list Developer Mode in its Windows desktop steps. The switch is in Settings → Privacy & Security.

With no Mac, that switch may be missing. Apple's guide says it only appears after you start pairing the iPhone with a Mac, or if it was paired with one before. pymobiledevice3 (Option 1) can reveal it with pymobiledevice3 amfi reveal-developer-mode. Then turn it on in Settings and restart when asked. For more fixes, see Developer Mode not showing on iPhone.

If your PC doesn't see your iPhone

Apple's support page suggests these checks:

  • If you use the Apple Devices app, open it, then connect the iPhone. It should appear in the sidebar.
  • If you never saw the Trust alert, or tapped Don't Trust, reset the iPhone's Location & Privacy settings.
  • If the phone doesn't chime or vibrate when plugged in, check the port for debris, then try another cable and USB port.
  • Update Windows and iOS to their latest versions.

Option 1: pymobiledevice3 (free, command line)

pymobiledevice3 is a free, open-source Python tool for working with iPhones, licensed under the GPL v3. It runs on Windows, Linux and macOS, and offers developer services, including location simulation, without Xcode. Its README compares it to Android's adb.

Install it

  1. Install iTunes, the docs' Windows prerequisite.
  2. Install uv, a tool installer that also downloads a suitable Python for you. In PowerShell, run: 
    powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"
  3. Open a new terminal, then install pymobiledevice3: 
    uv tool install --managed-python pymobiledevice3
  4. Plug in and unlock the iPhone, then check that the PC can see it: 
    pymobiledevice3 usbmux list

Set and clear the location

These iOS 17+ commands come from the docs. Replace the capital words with decimal coordinates. The -- lets negative numbers through.

# Simulate location (iOS >= 17.0)
pymobiledevice3 developer dvt simulate-location set -- LATITUDE LONGITUDE
# Play GPX route
pymobiledevice3 developer dvt simulate-location play route.gpx
# Clear simulated location
pymobiledevice3 developer dvt simulate-location clear

The command's help text gives an example: set -- 40.690008 -74.045843. Type the latitude first, then the longitude, with a space between them.

To find decimal coordinates, open Google Maps on a computer and right-click a spot. Google's help page says the latitude and longitude appear at the top of the pop-up, and clicking them copies them. Google writes them with a comma, as in 41.40338, 2.17403. In the command, leave out the comma.

The help text says set keeps its session open until you press Ctrl+C. Leave that window open while you need the simulated location. When you're done, press Ctrl+C, then run clear.

play moves the phone along a route saved as a GPX file.

The iOS 17.0–17.3 caveat

On iOS 17.4 and later, pymobiledevice3 builds its tunnel for you on Windows, with no driver and no Administrator rights. iOS 17.0 to 17.3 needs tunneld, a background helper that keeps a tunnel open, run from an Administrator terminal. It also needs a third-party driver that pymobiledevice3 doesn't ship or endorse. The docs advise updating to iOS 17.4 or later instead.

Best for: scripts, automated tests and CI (servers that run tests automatically). Its Python API lets a test suite set the location directly.

Option 2: GeoPort (free, point and click)

GeoPort is a free, open-source location app under the GPL v3, built on pymobiledevice3 with an interface inspired by iFakeLocation. Its website offers Windows, Mac and Linux builds. Donations are optional.

GeoPort's README lists iOS 17 and 18 on Windows and Mac. In November 2025, its developer replied in the iFakeLocation thread that iOS 18 and iOS 26 were confirmed working.

Check your iOS version first. GeoPort's latest GitHub release is still v4.0.2, from December 2024. Open reports on its issue tracker, all newer than that November 2025 reply, describe problems on newer iOS:

  • Issue #195 (September 2026): on iOS 27, GeoPort 4.0.2 reports that the location was set, but Maps on the phone doesn't move. On the same phone, pymobiledevice3 11.17.0 did move it.
  • Issue #188 (April 2026): on iOS 26.4.1, the location appears to change on the Windows side, but nothing changes on the phone.
  • Issue #186 (March 2026): after an update to iOS 26.3.1, the phone no longer shows up in GeoPort.
  • Issue #190 (June 2026): on iOS 26.5 with a Mac, the location reverts a few minutes after the iPhone is disconnected.

A proposed iOS 27 fix, pull request #194, had not been merged when we checked on 15 November 2026. If your iPhone runs iOS 26.4 or later, read the open issues before you install, or use pymobiledevice3 instead.

  1. Install iTunes. GeoPort's README says Windows needs iTunes for its USB service.
  2. Download the Windows build from GitHub or geoport.me.
  3. Run it with Administrator rights. The README says admin rights are required for iOS 17.
  4. Connect the iPhone. If Developer Mode is off, GeoPort can turn it on, but you'll have to remove your passcode temporarily.
  5. Pick a spot on the map and simulate the location.
  6. When you're done, click Stop Location. If you disconnected first, the README says to reconnect and click it.

GeoPort's FAQ, written for an earlier version, lists extras. It can connect over Wi-Fi after one USB pairing. It can replay a drawn or imported GPX track at walking, running, riding or driving speed. If you see "Unable to create tunnel within timeout" while running as Administrator, the FAQ blames Windows Firewall: allow GeoPort on both Public and Private networks.

Option 3: Wander Desktop for Windows

Wander is our product, so weigh this section with that in mind. Wander Desktop drives an iPhone plugged into your PC over a local USB tunnel, with nothing installed on the phone. These steps come from the download page:

  1. Install Apple Devices from the Microsoft Store, or iTunes from apple.com.
  2. Download Wander-Windows.zip and unzip the folder.
  3. Run Wander Desktop.exe. It's an unsigned indie build, so SmartScreen may warn you. SmartScreen is Windows' warning screen for apps it doesn't recognize. Click More info, then Run anyway.
  4. Approve the UAC admin prompt. Wander needs it for the device tunnel.
  5. Plug in your iPhone and click Connect Device. Then teleport, use the joystick, or run a route.

If Connect Device can't see your iPhone, tap "Trust This Computer" on the phone, and make sure Apple Devices or iTunes is installed.

These desktop steps don't mention Developer Mode. The download page's iPhone-app steps do.

Why the SmartScreen warning? The Mac and Windows builds are unsigned because code-signing certificates cost money every year. The warning is about that missing certificate. The desktop app is open source under the GPL v3, so you can read the code. The security page links to Wander's source on GitHub.

Several iPhones at once (beta). The Mac and Windows apps can hold a location across every connected iPhone. You can set one phone, a few, or all of them. Connect each phone first, then pick which ones move.

Price. The free plan gives you 1 teleport a day, plus 15 minutes of joystick and 3 routes a month, with no card. Pro costs $3.99 a month, $36 a year, or $80 once for lifetime. The pricing page says one license covers iPhone, Android, Mac and Windows. Its FAQ says Pro follows your account, not a device. Its yearly plan card, though, lists "Use it on up to 3 devices". If you want to move several iPhones at once, ask us about that limit before you buy the yearly plan. Wander's site doesn't list supported iOS versions, so try the free plan on your iPhone before you pay.

Option 4: install Wander on the iPhone, so the PC isn't needed afterward

The three desktop tools all run on the computer, with the iPhone connected to it. If you'd rather have the location changer on the phone itself, you can install the Wander iPhone app from Windows. The download page puts it at a one-time setup of about 10 minutes, with a free Apple ID. The Windows installer is a fresh beta and needs the free Apple Devices app.

  1. Install Apple Devices, plug in the iPhone and tap Trust.
  2. Run Wander-Installer-Windows.exe. If SmartScreen warns you, click More info → Run anyway, then approve the UAC prompt.
  3. Sign in with your free Apple ID. No paid developer account is needed.
  4. Click Install Wander. It signs the app and installs it on your iPhone.
  5. On the iPhone, go to Settings → General → VPN & Device Management, tap your Apple ID, and tap Trust. Then turn on Developer Mode and restart when asked.
  6. Install LocalDevVPN, a free tunnel app, from the App Store and connect it on Wi-Fi.
  7. Open Wander and tap Get Started.

After that, Wander re-signs itself, so you won't need the computer again. For why apps installed with a free Apple ID need re-signing at all, see why sideloaded apps expire after 7 days.

Which should you choose?

  • Scripts, automated tests or CI: pymobiledevice3. It's free. It needs no admin rights on iOS 17.4 and later. Its Python API makes it the better choice for automation.
  • A quick, free teleport with a map: GeoPort, if it supports your iOS version. It may not work on iOS 26.4 or later, so check its issue tracker first. Expect to install iTunes and run it as Administrator.
  • Routes, a joystick, several iPhones at once, or an app on the phone itself: Wander. Its free plan is limited, and Pro is paid. The builds are unsigned, and the Windows iPhone installer is in beta. Its site doesn't list supported iOS versions, so start with the free plan.

If a free tool does what you need, use it. If you do have a Mac and Xcode's Simulate Location misbehaves, see Xcode Simulate Location not working. Wander's full feature list is on the features page.

Afterward: get your real location back

  • pymobiledevice3: press Ctrl+C to end set, then run pymobiledevice3 developer dvt simulate-location clear.
  • GeoPort: click Stop Location. If you already unplugged, reconnect first.
  • Wander: the Panic button snaps you back to your real GPS in one tap.

If the phone seems stuck, iFakeLocation's README suggests turning Location Services off and on. Our guide to getting your real location back has more fixes.

Why iFakeLocation and idevicesetlocation stopped working on iOS 17

Before iOS 17, tools first mounted a developer disk image on the iPhone. That is an Apple-signed file that adds developer features to the phone. Then they called a small location service. iFakeLocation's README still describes downloading these images, and libimobiledevice's idevicesetlocation asks you to mount one when it fails on older iOS.

The pymobiledevice3 docs explain that, starting with iOS 17.0, Apple moved its developer services, including location simulation, behind an encrypted tunnel to the device. Two more terms help:

  • A tunnel is a private, encrypted link between computer and iPhone. Developer commands travel inside it.
  • RemoteXPC is the Apple protocol that DVT and the other developer services use.

Tools that didn't adopt the new route stopped working. The public record shows it:

  • June 2023: in pymobiledevice3 issue #471, its maintainer said location simulation had been reworked to run over RemoteXPC. Support shipped in pymobiledevice3 v2.2.0 that July.
  • May 2024: in issue #1029, the maintainer noted that iOS 17 uses a DVT channel instead.
  • June 2025: libimobiledevice changed idevicesetlocation so that, when it can't start the location service on iOS 17 or later, it prints: "Note: This tool is currently not supported on iOS 17+". The note is still in its source code.
  • iFakeLocation: issue #169, asking for iOS 17 support, has been open since 14 January 2024. The app's latest release, v1.7.0, is from August 2022.

What about 3uTools?

3uTools is a different case. As of its March 2024 troubleshooting page, 3uTools offered Virtual Location on iOS 17 and later. That page covers errors -214 and -303 on those versions, and most of its fixes involve Windows drivers:

  • Error -214: first update 3uTools. If a driver is missing from Device Manager, the page says Windows 10 or 11 should be newer than version 22H2.
  • Error -303: if Device Manager shows a warning icon on a network driver named "UsbNcm Network(WeTest)" or "iOS UsbNcm Network", the page gives a registry fix. It also says another location tool's driver, such as iAnyGo's, can conflict. Uninstall that driver and try again.
  • Its Virtual Location feature isn't supported on 32-bit Windows 10 or 11.

If 3uTools shows one of those errors, start with that page.

Use it responsibly

Setting a phone's location is useful for testing location features, previewing places before a trip, and protecting your privacy. Wander's site describes it as for personal and testing use. Some apps' terms forbid changing your location, and if you use any of these tools with another app or service, you're responsible for following its rules.
